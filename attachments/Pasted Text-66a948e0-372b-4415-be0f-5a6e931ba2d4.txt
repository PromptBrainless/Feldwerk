## Zerlegung des Systemprompts

Der Text ist kein einzelner Befehl, sondern fünf Schichten. Andere Umgebungen sollen genau so damit umgehen.

1. **Rolle** — ein Produkt: Editor + Player als eine Android-APK, sideload an Freunde, keine Stores.
2. **Grenzen** — nur Android. iOS/Desktop dürfen keine Architekturentscheidung ziehen. Plugin-Sicherheit darf pragmatisch sein, Datenverlust nicht.
3. **Arbeitsvertrag** — Entwurf vor Code, ADR max. 15 Zeilen, kleine buildbare Schritte, keine erfundenen Versionen, `runtime/` kennt `editor/` nicht, Abschluss immer: geändert / getestet / offen.
4. **Technik** — eine Web-Codebasis, APK über Capacitor. PixiJS rendert, Preact ist der Editor, JSON+Schema ist das Projektformat.
5. **Reihenfolge** — M0 Fundament → M1 Durchstich → M2 Events/DB → M3 Kampf → M4 Plugins → M5 Chargen/Assets → M6 Einzelspiel-APK.

Daraus folgen drei harte Regeln für jeden Agenten (Codespace, Actions, Grok, Copilot):

- Versionen nur aus offizieller Doku oder `package.json`.
- Kein zweiter Stack „nebenbei“. Native Runtime nur nach eigenem ADR, falls M1 die 60 FPS verfehlt.
- Der Hauptzweig muss eine APK erzeugen können. Kaputte Zwischenstände gehören nicht auf `main`.

## In einer anderen Umgebung starten

```bash
git clone https://github.com/PromptBrainless/rpgmaker.git
cd rpgmaker
npm install
npm test
npm run dev
```

APK (einmalig Android-Plattform anlegen, danach committen):

```bash
npx cap add android
npm run apk:debug
```

Oder auf GitHub: Action **build-apk** → `workflow_dispatch`. Anleitung: `docs/build.md`.
